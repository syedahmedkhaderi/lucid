# Known limitations

The current code is a rebranded, tested adaptation of NexQ v3.0.0. It is not yet a production-ready Lucid release.

- A meeting can select up to ten documents from its home, borrowed, and included General workspaces. Workspace membership still caps each workspace at ten documents and 500 MiB of aggregate source files. Older workspaces that already exceed either workspace limit are not migrated, though new additions are blocked when they exceed either bound.
- On the test Mac, idle Settings eventually enumerated built-in input/output devices after relaunch, but fresh meeting sessions still showed both meters at zero and produced no transcript from test playback. Device selectors inside the active meeting remained at “Loading…”. Lucid logged `Starting output-tap recording failed (CoreAudio status 268451843)` and recommended checking System Audio Recording access. Its bundle includes `NSAudioCaptureUsageDescription`, but the macOS permission state was not confirmed or changed. Check System Settings → Privacy & Security → Screen & System Audio Recording, allow Lucid if it is off, then restart and retest. Earlier local-model meeting tests did work; this Mac is not verified for reliable live capture until the retest succeeds. [Apple's Core Audio tap documentation](https://developer.apple.com/documentation/CoreAudio/capturing-system-audio-with-core-audio-taps) describes the required usage string and first-use permission prompt.
- Uploaded files are capped at 50 MB each and empty files are rejected. Supported imported file types are PDF, DOCX, PPTX, TXT, and Markdown. Library-uploaded, text based PDF citations include the source page when page extraction succeeds; older PDFs are backfilled on the next index pass if their copied file remains available. PPTX extraction preserves slide numbers and basic table rows. Legacy DOC/PPT, scanned-PDF OCR, folder-PDF page citations, speaker notes, chart/image interpretation, and opening a PDF directly at the cited page remain unsupported.
- Gemini 3.5 Transcribe Live is implemented with a local mock-WebSocket test suite, but it has not been authenticated against a real Google account or tested with real meeting audio. The Gemini text-answer path has been exercised using a validated account during synthetic live meetings; this does not verify the separate Gemini Live transcription endpoint. Unexpected connection loss requires the user to restart transcription or choose another provider; automatic retry is limited to planned session refresh. Accuracy, latency, model/account access, billing and Mandarin/technical-term behavior are unverified.
- The live brief keeps up to six scope-bound, source-linked facts. A fact must include an exact excerpt from its cited passage; its names and numbers must occur in the excerpt, and at least half of its distinct content words must overlap. The quote is visible in the panel. This lexical check cannot prove semantic entailment or resolve conflicting values.
- Workspace search has a local source-fact cache for a bounded set of explicitly labeled numeric fields, ISO dates, identifiers, suppliers, materials, parties, acronyms, requirements, obligations, and payment terms. It stores exact quotes, source locations, source hashes, and extraction status; migrations v20–v21 backfill indexed passages. Workspace chat injects attribute matches only from its current scope and flags conflicts for the same captured subject and conditions. A narrow direct numeric/date lookup returns a local answer without generation only when one source, subject, value, and condition set match and the cited candidate made it into context. The extractor does not find facts in unlabeled prose, cover all clauses or technical vocabulary, or prove semantic meaning. Document precedence is not modeled; ambiguous cache cases use the normal evidence-grounded model path.
- Workspace chat now instructs models to abstain when source material is missing or conflicting, cite factual claims with available labels, and treat prior AI replies as context rather than evidence. Backend validation confirms citation labels refer to sent material, but it cannot prove every natural-language claim is supported; this remains unmeasured.
- Google's [current model catalog](https://ai.google.dev/gemini-api/docs/models) lists Gemini 4 Hydrogen as `gemini-4-hydrogen`; this app has not confirmed account eligibility or free-tier access, and does not yet have a documented task-based model registry.
- Cloud processing is opt-in, but Lucid does not enforce free-tier-only billing or restrict the selected cloud provider to a free plan. Cloud requests may incur charges.
- LLM Settings now supports individually validated and tab-separated bulk credential profiles. Secrets live in the OS credential store; SQLite stores only labels, a masked suffix, the optional user-entered project ID, and validation time. Duplicate keys are rejected, and selecting a different profile is an explicit user action. Provider selection is manual; key strings are not used to infer a provider or Google project. Lucid does not rotate credentials on rate-limit or quota errors. Provider quota balances, model-availability checks per profile, actual last-use timestamps, and runtime error history are not yet tracked; deleting a local profile does not revoke it at the provider.
- Saved API secrets are no longer returned to the renderer. LLM and speech tests resolve keys in Rust; the settings UI shows key presence and accepts replacements without revealing the saved value. The non-secret setting reader is restricted to region, endpoint and model fields.
- The default Private Local mode blocks content-bearing requests to cloud speech, LLMs, subscription CLIs, remote model endpoints, Gemini context caching, and non-local embeddings. Cloud use requires switching to Cloud processing allowed outside an active meeting/request. The privacy boundary has not had an independent security audit; Private Local cannot verify the behavior of local software you install, and meeting records are not encrypted at rest.
- The new triangular compact overlay placement math has unit tests, but the interactive native resize, monitor handling, and cross-platform visual behavior have not been runtime-tested.
- The performance goals (cached answer ≤300 ms, typical answer 1–2.5 s, initial transcript ≤500 ms, accuracy ≥98%) are unmeasured.
- Google's [pricing page](https://ai.google.dev/gemini-api/docs/pricing) says Gemini 3.5 Transcribe Live free-tier content may be used to improve products. Cloud processing is opt-in, but the provider/account's current terms still determine how submitted data is handled.
- Windows is the primary production target, but no Windows build, installer, or audio capture test has been run. Tauri's macOS Finder-based DMG layout step timed out; the current HFS+ DMG was assembled separately, checksum-verified, and mounted successfully. Gatekeeper and notarization behavior are untested.
- App Store/notarized distribution and automatic updates are not configured. Updates remain disabled because Lucid does not own a signing key or release feed.
- Dependency scans on 2026-11-27 found no known vulnerabilities after three Rust lockfile updates, but nine RustSec warnings remain for unmaintained/yanked crates and a Linux GTK `glib` unsoundness advisory. See [`SECURITY.md`](SECURITY.md).
- A generated dependency metadata inventory is checked in, but it is not a legal license review. The 98 npm production packages lacking a declared SPDX license expression need classification, required license texts/notices need to be collected and release-checked, and a release security review remains outstanding.
- The host Node version is 24.1.0; the pinned jsdom package declares Node 24.15.0+ or 22.22.2+, so npm reports an engine warning even though build and tests pass.
